# Cloud Concepts and Version Control Reflection

In my daily digital routine, I frequently use three major cloud services: Google Drive, AWS EC2, and Google App Engine. Understanding their service and deployment models helps me appreciate how modern computing resources are delivered and managed.

First, **Google Drive** is a Software as a Service (SaaS) running on a Public Cloud. As a user, I do not need to manage the underlying server hardware or operating system; I simply access the software directly through the web to store and share files.

Second, **AWS EC2 (Elastic Compute Cloud)** represents Infrastructure as a Service (IaaS), operating primarily as a Public Cloud. With EC2, I am provided with virtual servers where I can configure the operating system, storage, and networking parameters. This offers high flexibility and complete control over the computing environment.

Third, **Google App Engine** functions as a Platform as a Service (PaaS) on a Public Cloud. It allows developers to deploy code directly without worrying about managing virtual machines or network configurations. The platform handles scaling and server provisioning automatically.

Furthermore, integrating version control tools like **Git** and **GitHub** is vital for modern cloud projects. Git enables developers to track changes, manage codebase branches, and revert to previous states if issues arise. GitHub provides a centralized, cloud-hosted platform that fosters seamless collaboration among team members. In cloud computing, where infrastructure is increasingly defined as code (IaC), using Git and GitHub ensures that system configurations and software deployments remain traceable, secure, and reproducible across different deployment environments.
